Notas de design (proposta A — versão inicial, sem plugins novos)

Recorte da proposta A que sai só do que o Backstage já tem: catálogo, plugin Kubernetes (backend já configurado), catalog-graph, api-docs e TechDocs. O código novo fica em módulos do app (idp/packages/app/src/modules), como entityHeader e entityDependencies — nenhum plugin nem backend novo.

  • Header — título, tipo, descrição, owner, System, Domain e lifecycle: entidade e relações ownedBy/partOf do catálogo (o header customizado de #124 já lê quase tudo).
  • Breadcrumb Domain → subdomain → System: catalogApi.getEntityByRef subindo partOf do System até o Domain raiz.
  • Contagem nas abas — só APIs e Dependencies, que contam relações do catálogo (providesApi/consumesApi, dependsOn). Kubernetes fica sem contagem: a aba é a do plugin.
  • Links — anotações backstage.io/source-location e backstage.io/edit-url.
  • Running version substitui o card Latest commit: tag da imagem dos pods via kubernetesApi/useKubernetesObjects; o link do commit é montado a partir da tag + github.com/project-slug, sem chamar a API do GitHub.
  • Depends on agrupado por papel: relações dependsOn + spec.type de cada Resource (getEntitiesByRefs); kubernetes-cluster vai para "Runs on", o resto para "Data".
  • Relations — EntityCatalogGraphCard do catalog-graph com altura reduzida (o desenho fica o do plugin, não o SVG do mockup).
  • APIs — cards do api-docs quando houver relação; estado vazio próprio quando não houver.
  • Kubernetes — aba padrão do plugin, sem modificação. Saem os cards customizados por cluster e o card Promotion.
  • About — aba no fim da barra (link compartilhável: /about) com dois cards lado a lado, Metadata e Annotations. Fonte: a própria entidade.
  • Docs (TechDocs) — sem mudança de fonte.

Fica para depois (precisa de plugin ou integração nova):

  • Aba Environments com ArgoCD Applications (sync, health, revision) — plugin do ArgoCD.
  • Latest commit (mensagem, autor, data) e Language — GitHub API.
  • Kubernetes redesenhado (pod, imagem e restarts sem expandir; card de promoção) — exige substituir a aba do plugin.
  • Endpoints servidos pelo serviço sem entidade API — só existem na documentação do repo.
