# aws_iam_saml_provider

|  |  |
|---|---|
| **Description** | Registers the Identity Center SAML metadata in IAM so the Client VPN endpoint can federate authentication through it — the piece that lets `access_group_id` on an authorization rule mean something. |
| **Provider** | `terraform · aws` |
| **Type** | `IAM SAML provider` |
| **Layer** | `04 · connectivity` |
| **State** | `connectivity` |
| **Dependencies** | `None` in Terraform — but consumes a metadata XML file exported by hand from the Identity Center SAML application (layer 00, not Terraform) |
| **Produces** | `arn` — consumed by `aws_ec2_client_vpn_endpoint.hub.authentication_options.saml_provider_arn` |
| **Teardown** | Torn down with this root every night; re-created from the same metadata file each time |

## Examples

- Consumes a metadata XML that is not generated by Terraform and cannot be: the Identity Center `CreateApplication` API only supports custom OAuth 2.0 applications — the SAML application itself is a console-only artifact (see `saml-application.md`), and its exported metadata file is the easiest prerequisite to forget because nothing here reminds you it is missing until the provider call fails.
- The file is read with `file(var.saml_metadata_path)` and is gitignored — never committed, since this repo is public and the metadata identifies a real Identity Center instance.
- The up-script for this layer stops with an explicit instruction if the file is absent, rather than letting the apply fail deep inside the provider with a message that does not explain what is missing.
