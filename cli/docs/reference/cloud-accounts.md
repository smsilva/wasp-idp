# Cloud accounts

A cloud account is an AWS account where the platform can create things (ADR 0029). The platform stores no per-account secret: it assumes a role in the account from the base credential of `platform init --aws-profile`. Any user registers their own accounts, without approval; ownership is proven by the trust policy, which only whoever administers the account can apply.

| Command | What it does |
|---|---|
| `platform cloud account add <name> --role-arn <arn> [--region <region>]...` | registers the account and prints the trust policy to apply to the role |
| `platform cloud account list` | NAME, VENDOR, ACCOUNT, STATUS, VALIDATED (and OWNER for admins) |
| `platform cloud account get <name>` | status and the trust policy |
| `platform cloud account verify <name> [--wait]` | asks the provider for a new verification |
| `platform cloud account remove <name>` | removes the registration; the role stays in the AWS account |

## Trust policy

The policy trusts the platform base credential, with a condition on `sts:ExternalId`. The API generates the ExternalId, one per account, never accepts it from the client and keeps it out of the journal: it prevents someone from registering another person's role.

```json
{
  "Effect": "Allow",
  "Principal": { "AWS": "arn:aws:iam::<platform-account>:user/<base-credential>" },
  "Action": "sts:AssumeRole",
  "Condition": { "StringEquals": { "sts:ExternalId": "<generated by the API>" } }
}
```

## Status

The provider assumes the role twice: with the ExternalId it must work, without it it must fail. It revalidates every 6 hours and, while the account is not `ready`, retries with increasing intervals up to 15 minutes.

| Status | Meaning |
|---|---|
| `pending` | not verified yet |
| `TrustNotEstablished` | the role does not trust the platform with this ExternalId: apply the trust policy from `get` |
| `ExternalIdNotEnforced` | the role trusts without requiring the ExternalId: add the condition |
| `AccountMismatch` | the role is in another account |
| `VerificationFailed` | another AWS error, in `message` (for example, the base credential expired) |
| `ready` | the platform assumes the role, and only with the ExternalId |

## Rules

- Each account belongs to whoever registered it: other users neither see nor remove it (`403`); `platform-admins` see all of them.
- The same role is not registered twice (`409`), compared by account and role name, case-insensitive and without the path.
- Without a base credential, `add` answers `409` asking for `init --aws-profile`.
