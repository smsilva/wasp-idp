# Without a browser

The walkthrough has **one human step, the sign-in**. `scripts/demo/cli-smoke` (#179) runs the flow **unattended**: `init`, sign-in with the test user (`platform-users`), `platform status` with only the capability and its status, the same user seen by an agent through `platform-mcp` (`whoami` over stdio), the `403` refusal when creating a domain, an environment created with `--wait`, whose gateway answers at `http://*.<name>.localhost:7080`, and deleted, sign-in with the test admin, `platform status` with the providers (and one capability in full, its driver and `depends on`; `404` for an unknown one), `catalog import idp/catalog/` (applied, then `nothing to do`), the templates (`list` as a regular user, `403` refusal on `create`, `render` of the seed with no `${{` left over, the import plan of the Backstage template with the `steps` ignored), the connections (`403` refusal for a regular user; as admin, `add --no-browser` returns the manifest flow URL and the start page takes the manifest to the org, a forged `state` is refused, and `remove`), the refusals of `component create` before anything reaches GitHub (unknown system `422`, a `--param` outside the schema `422`, a name already in the index `409`, a connection in `AppNotCreated` `409`), the OCI registries (`registry add` refused to a regular user `403`; as admin, `NoDefaultRegistry` when the cluster has no default, `add` with `--vendor` and with `--scm-connection`, a host other than `ghcr.io` and a taken address refused, `ready` once `https://ghcr.io/v2/` answers, `set-default` leaving one default, `remove` refused while a version is in the registry), the refusals of `build create` before anything reaches GitHub (a user outside the owner team `403`, unknown component `422`, a malformed `--version` `422`, an unknown `--registry` `422`, a GHCR of another org `RegistryNotWritableByCI`, a repo whose org has no connection `409`, and an empty `build list`), the Workload Spec (`workload spec validate` of the rendered seed and of a Score with an unknown resource type, `spec get` of a `Version` written by `kubectl` (`403` outside the owner team, then by `--branch` and as JSON), `SpecNotIndexed` for a `Version` without the spec, and `404` for a branch with no version), a Workload Instance (`workload deploy --wait` of a `Version` written by `kubectl` with a public image by digest in an environment of the test user, `list`, `get`, `history`, `rollback` to the previous success, `running in` in `catalog component get` and `remove`; a pod in the vcluster that reaches the instance's Service by its DNS name; a second instance of the same component with `deploy --instance`, `list` with its `COMPONENT`, `get --component` refused as ambiguous, the component's Service without the pods of the second instance, and `remove --instance`; `403` for the environment's owner outside the component's owner team, `404` for a version outside the index, `409` for a rollback to a failed revision, and `ResourcesNotSupported` for a Score with a resource type without provider), the plan of an environment (`workload apply --dry-run` with `1 to add`, `apply --wait`, the same plan `unchanged`, a new replica count as `1 to change`, `403` for a plan with a component outside the user's teams, and `--prune` of an empty plan), a Postgres provisioned by the Forager (`deploy --wait` until the resource is `Ready`, with its `resource` line in the output of the deploy itself, an app that connects to it with `psql`, the derived Resource in the catalog, and the `ResourceRequest` released on `remove`), the binding policy of an environment (`policy set` refused for `compose` without an instance, then `postgres` → `compose` in `shared-pg`, `policy get` with its layers, the policy of the profile `ephemeral` (`compose` in `shared-pg`, `404` for an unknown profile, `403` to change it as a regular user), a deploy whose app connects to its own database in the shared instance, and the database dropped on `remove`), a database that already exists (`policy set` refused for `bind` without its values, a `bind` item with `class: restored` pointing at a database restored by hand in `shared-pg` and its bindable Secret, `422` for a `--resource-class` of a resource the version does not have, a deploy with `--resource-class db=restored` whose app connects to `restored`, a plan with `resourceClasses: {db: restored}` that `apply --dry-run` shows as `unchanged` and as `1 to change` without the class, and the database kept on `remove`), an instance reached from outside through `dns` and `route` and its golden signals (`workload signals` after a burst of `curl`, with traffic, errors, latency and saturation from Prometheus, and `--window 1d` refused), a cloud account (`503 NoProviderForCapability` when `init` ran without `--aws-profile`; with one, a role the platform does not assume ends up `TrustNotEstablished`, and another user neither sees it nor registers the same role) and `logout`. The smoke does not create an App: the manifest flow needs a browser and an org owner, so creating, installing and reaching `ready` stays in the manual walkthrough of the [GitHub connection](scm-connection/github/create-app.md), and so do the happy paths of [component create](components/create.md) and [build create](builds/create.md). It stops at the first failure, with a non-zero exit code.

Each step opens with `== [<n>/<total> · <elapsed>] <step>`, so a slow `--wait` reads apart from a hung one, and a refusal the step expects is printed as `  expected refusal: <message>`, never as a bare `✗`. Without a terminal (`cli-smoke > smoke.log`), the output has no colors.

```bash
scripts/demo/cli-smoke              # from scratch, with platform init

# reuses the platform-local that is already up
scripts/demo/cli-smoke \
  --skip-init
```

!!! note
    The users `platform-smoke` and `platform-smoke-admin` and the client `platform-smoke` exist **only on the local target**. The rationale for the password grant is in `platform/keycloak/README.md`.
