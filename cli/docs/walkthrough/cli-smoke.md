# Without a browser

The walkthrough has **one human step, the sign-in**. `scripts/demo/cli-smoke` (#179) runs the flow **unattended**: `init`, sign-in with the test user (`platform-users`), the `403` refusal when creating a domain, an environment created with `--wait` and deleted, sign-in with the test admin, `catalog import idp/catalog/` (applied, then `nothing to do`), the templates (`list` as a regular user, `403` refusal on `create`, `render` of the seed with no `${{` left over, the import plan of the Backstage template with the `steps` ignored), the connections (`403` refusal for a regular user; as admin, `add --no-browser` returns the manifest flow URL and the start page takes the manifest to the org, a forged `state` is refused, and `remove`), the refusals of `component create` before anything reaches GitHub (unknown system `422`, a `--param` outside the schema `422`, a name already in the index `409`, a connection in `AppNotCreated` `409`), the refusals of `build create` before anything reaches GitHub (a user outside the owner team `403`, unknown component `422`, a malformed `--version` `422`, a repo whose org has no connection `409`, and an empty `build list`), the Workload Spec (`workload spec validate` of the rendered seed and of a Score with an unknown resource type, `spec get` of a `Version` written by `kubectl` (`403` outside the owner team, then by `--branch` and as JSON), `SpecNotIndexed` for a `Version` without the spec, and `404` for a branch with no version), a Workload Instance (`workload deploy --wait` of a `Version` written by `kubectl` with a public image by digest in an environment of the test user, `list`, `get`, `history`, `rollback` to the previous success, `running in` in `catalog component get` and `remove`; a pod in the vcluster that reaches the instance's Service by its DNS name; a second instance of the same component with `deploy --instance`, `list` with its `COMPONENT`, `get --component` refused as ambiguous, the component's Service without the pods of the second instance, and `remove --instance`; `403` for the environment's owner outside the component's owner team, `404` for a version outside the index, `409` for a rollback to a failed revision, and `ResourcesNotSupported` for a Score with a resource type without provider), the plan of an environment (`workload apply --dry-run` with `1 to add`, `apply --wait`, the same plan `unchanged`, a new replica count as `1 to change`, `403` for a plan with a component outside the user's teams, and `--prune` of an empty plan), a Postgres provisioned by the Forager (`deploy --wait` until the resource is `Ready`, an app that connects to it with `psql`, the derived Resource in the catalog, and the `ResourceRequest` released on `remove`), the binding policy of an environment (`policy set` refused for `compose` without an instance, then `postgres` → `compose` in `shared-pg`, `policy get` with both layers, a deploy whose app connects to its own database in the shared instance, and the database dropped on `remove`), a database that already exists (`policy set` refused for `bind` without its values, a `bind` item with `class: restored` pointing at a database restored by hand in `shared-pg` and its bindable Secret, `422` for a `--resource-class` of a resource the version does not have, a deploy with `--resource-class db=restored` whose app connects to `restored`, a plan with `resourceClasses: {db: restored}` that `apply --dry-run` shows as `unchanged` and as `1 to change` without the class, and the database kept on `remove`), a cloud account (`409` asking for `--aws-profile` without a base credential; with one, a role the platform does not assume ends up `TrustNotEstablished`, and another user neither sees it nor registers the same role) and `logout`. The smoke does not create an App: the manifest flow needs a browser and an org owner, so creating, installing and reaching `ready` stays in the manual walkthrough of the [GitHub connection](scm-connection/create-app.md), and so do the happy paths of [component create](components/create.md) and [build create](builds/create.md). It stops at the first failure, with a non-zero exit code.

```bash
scripts/demo/cli-smoke              # from scratch, with platform init

# reuses the platform-local that is already up
scripts/demo/cli-smoke \
  --skip-init
```

!!! note
    The users `platform-smoke` and `platform-smoke-admin` and the client `platform-smoke` exist **only on the local target**. The rationale for the password grant is in `platform/keycloak/README.md`.
